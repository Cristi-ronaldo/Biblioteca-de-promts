Biblioteca de prompts técnicos

Instrucciones reutilizables para documentar código, redactar correos técnicos y analizar incidencias con ayuda de inteligencia artificial.

¿Cómo se usa? Elige el prompt que necesites, pulsa Copiar prompt y pégalo en tu asistente de IA. Después reemplaza los textos entre corchetes con tu información. Si prefieres que el sistema te haga las preguntas, ejecuta python simulador_prompts.py en la carpeta del proyecto.
Documentación

Documentar código

Convierte un archivo o una función en documentación clara: qué hace, qué recibe, qué devuelve y qué casos especiales contempla.

Ideal para: código heredado, entregas a cliente, APIs internas. Tiempo ahorrado: de 1 hora a 5 minutos.
Ver prompt completo 
Actúa como un ingeniero de software senior especializado en documentación técnica.

CONTEXTO
Tengo el siguiente código escrito en [LENGUAJE]. Necesito documentarlo para que lo entienda [PÚBLICO: compañero nuevo / cliente sin perfil técnico / otro desarrollador].

CÓDIGO
"""
[PEGA AQUÍ EL CÓDIGO]
"""

TAREA
Analiza el código y genera la documentación con esta estructura:

1. Resumen en 2 o 3 líneas: qué hace el código y para qué se usa.
2. Requisitos: dependencias, librerías o datos que necesita para funcionar.
3. Funciones o clases: para cada una indica nombre y propósito, parámetros (tipo y significado), valor de retorno y errores que puede lanzar.
4. Ejemplo de uso realista y ejecutable.
5. Casos límite o comportamientos que conviene vigilar.
6. Posibles mejoras (máximo 3, solo si son relevantes).

REGLAS
- Escribe en español claro y directo.
- No inventes funciones, parámetros ni comportamientos que no estén en el código.
- Si algo no se puede deducir del código, indícalo como "no es posible determinarlo".
- Usa formato Markdown y bloques de código cuando corresponda.
- No repitas el código completo en la respuesta; solo las partes necesarias.
Comunicación

Redactar correo técnico

Escribe correos profesionales sobre mantenimientos, avances, problemas o solicitudes, con el tono y la estructura adecuados.

Ideal para: avisos de mantenimiento, reportes, respuestas a clientes. Tiempo ahorrado: de 30 minutos a 2 minutos.
Ver prompt completo 
Actúa como un especialista en comunicación técnica dentro de una empresa de tecnología.

CONTEXTO
Necesito redactar un correo sobre el siguiente tema:
- Destinatario: [QUIÉN LO RECIBE: cliente / jefe / equipo de desarrollo / proveedor]
- Objetivo del correo: [INFORMAR / PEDIR ALGO / RESPONDER / DISCULPARME]
- Tono deseado: [PROFESIONAL Y CERCANO / FORMAL / DIRECTO / EMPÁTICO]
- Nivel técnico del destinatario: [ALTO / MEDIO / NULO]
- Puntos clave que debe incluir:
  1. [PUNTO 1]
  2. [PUNTO 2]
  3. [PUNTO 3]
- Contexto adicional: [FECHAS, SISTEMAS, ANTECEDENTES, PLAZOS]
- Acción que espero del destinatario: [RESPONDER / APROBAR / EJECUTAR / NADA]

TAREA
Redacta el correo con esta estructura:
1. Asunto claro y específico (máximo 10 palabras).
2. Saludo breve.
3. Primer párrafo: el motivo del correo en una o dos frases.
4. Cuerpo: los puntos clave, en orden de importancia.
5. Cierre: la acción esperada y el plazo, si aplica.
6. Despedida profesional.

REGLAS
- Escribe en español neutro y profesional.
- Frases cortas. Nada de párrafos de más de 4 líneas.
- Si el destinatario no es técnico, evita siglas o explícalas entre paréntesis.
- No inventes datos, fechas ni compromisos que no te haya dado.
- No uses lenguaje alarmista ni culpabilizador.
- Entrega el correo listo para copiar y enviar, sin comentarios adicionales.
- Al final, sugiere una versión de asunto alternativa.
Soporte

Analizar incidencias

Ordena el análisis de una falla: impacto, hipótesis ordenadas, cómo confirmarlas, mitigación inmediata y prevención.

Ideal para: caídas, errores intermitentes, reportes post-incidente. Tiempo ahorrado: evita horas de prueba y error.
Ver prompt completo 
Actúa como un analista de incidencias senior (SRE / soporte técnico nivel 3).

CONTEXTO
- Sistema afectado: [NOMBRE DEL SISTEMA O SERVICIO]
- Síntoma observado: [QUÉ ESTÁ FALLANDO, CON EL MAYOR DETALLE POSIBLE]
- Cuándo empezó: [FECHA Y HORA APROXIMADA]
- Frecuencia: [SIEMPRE / INTERMITENTE / UNA SOLA VEZ]
- Usuarios o procesos afectados: [QUIÉNES Y CUÁNTOS]
- Impacto en el negocio: [ALTO / MEDIO / BAJO, Y POR QUÉ]
- Cambios recientes: [DEPLOY, ACTUALIZACIÓN, CAMBIO DE CONFIGURACIÓN O "NINGUNO"]
- Logs o mensajes de error:
"""
[PEGA AQUÍ LOS LOGS]
"""

TAREA
Entrega un análisis con este orden:

1. Resumen ejecutivo en 3 líneas, entendible para alguien no técnico.
2. Impacto: a quién afecta, desde cuándo y qué se pierde mientras no se resuelve.
3. Hipótesis ordenadas de mayor a menor probabilidad, con el motivo de cada una.
4. Para cada hipótesis: cómo confirmarla o descartarla (comandos, consultas, revisión de configuración o preguntas al equipo).
5. Mitigación inmediata: qué hacer ahora para reducir el impacto.
6. Solución definitiva probable y qué se necesita para aplicarla.
7. Prevención: 3 acciones concretas para evitar que se repita.
8. Información que falta y que conviene pedir.

REGLAS
- No afirmes una causa como segura si no está confirmada por los datos.
- Separa claramente "hecho observado" de "hipótesis".
- Si los logs no alcanzan, dilo y explica qué evidencia hace falta.
- Usa español claro; explica cualquier término técnico que aparezca.
- Prioriza siempre reducir el impacto antes de buscar la causa raíz.

Ideal para: cualquier tarea nueva que quieras estandarizar. Ventaja: respuestas más claras desde el primer intento.

FORMATO DE SALIDA
[INDICA LA ESTRUCTURA EXACTA: secciones, tablas, longitud máxima, idioma.]
